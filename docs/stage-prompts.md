# Промты для разработки по этапам

Каждый блок ниже можно целиком отправлять в новый чат Codex. Запускайте этапы по порядку. Новый чат должен работать в том же репозитории.

## Этап 1 — фундамент, БД, пользователи, Dashboard

```text
Продолжи разработку проекта «Ритм» в текущем workspace. Это этап 1 из 8.

Сначала полностью прочитай docs/project-brief.md и docs/work-status.md, затем исходное полное ТЗ, если оно доступно в текущем чате. Осмотри весь текущий Git diff: в предыдущем чате создан непроверенный черновой skeleton. Не считай его правильным, но сохраняй полезные части и не уничтожай изменения без необходимости.

Цель этапа: получить запускаемый и проверенный фундамент приложения на PHP 8.2+ и MySQL 8/MariaDB:
- понятная структура каталогов и front controller;
- конфигурация через .env/.env.example без секретов;
- PDO, единая обработка ошибок, production/development режимы;
- нормализованная первичная БД, внешние ключи и критические индексы;
- регистрация, login/email + пароль, logout;
- password_hash/password_verify, session regeneration, CSRF, XSS escaping, secure cookie flags, rate limit входа;
- роли user/admin как архитектурная заготовка;
- строгая изоляция данных пользователей;
- mobile-first Dashboard с незавершённой, следующей и последней тренировкой и быстрыми действиями;
- минимальный аккуратный CSS, чтобы этап можно было реально открыть на iPhone;
- базовый seed справочника упражнений из ТЗ.

В этом этапе не реализуй полноценно импорт, проведение тренировки и offline; оставь только безопасные интерфейсы/заглушки, если они нужны для навигации. Если черновой код будущих этапов ломает приложение, исправь или изолируй его, не выдавая за завершённый.

Обязательно создай/обнови README.md, INSTALL.md, CHANGELOG.md, docs/database.md и docs/work-status.md. Добавь простую команду установки БД и понятный локальный запуск. Выполни php -l для всех PHP-файлов и доступные smoke-тесты. Если есть MySQL/MariaDB, проверь импорт schema/seed; иначе явно зафиксируй непроверенное место. Не создавай коммит, если я отдельно не попросил. В финале кратко перечисли результат, проверки и что остаётся этапу 2.
```

## Этап 3 — проведение силовой тренировки

```text
Продолжи проект «Ритм» в текущем workspace. Это этап 3 из 8. Этапы 1–2 должны быть завершены.

Сначала прочитай docs/project-brief.md, docs/work-status.md, docs/json-format.md, docs/database.md и текущий код. Запусти существующие тесты.

Реализуй основной mobile-first поток силовой тренировки:
- readiness за 10–15 секунд: сон, энергия, готовность, необязательные вес и комментарий;
- раздельные workout_plan и workout_session; создание/продолжение незавершённой сессии;
- карточки упражнений без горизонтальных таблиц: план, RIR, отдых, инструкция, прошлый результат;
- быстрый ввод «вес → повторы → RIR → готово», предзаполнение и кнопки изменения;
- warmup/working без смешивания объёма;
- autosave каждого подхода и существенного действия на сервер;
- статусы pending/active/waiting/completed/skipped;
- «оборудование занято», пропуск с причиной, замена упражнения с original/actual/reason/time;
- дискомфорт: область, 1–10, комментарий без медицинских выводов;
- оценка упражнения too_easy/normal/too_hard;
- редактирование подхода с audit log;
- optimistic locking/version и понятный конфликт нескольких вкладок;
- rest timer на timestamp: pause/reset/+30/finish early, vibration/audio/visual signal в пределах возможностей браузера.

На этом этапе online autosave должен быть надёжным; полноценная offline-очередь будет в этапе 4. Добавь серверную validation, проверку user_id для каждого endpoint и тесты критических переходов/изоляции. Проведи ручной mobile smoke flow от readiness до нескольких упражнений. Обнови CHANGELOG.md и docs/work-status.md. В финале перечисли проверки и известные ограничения iOS timer.
```

## Этап 4 — PWA и offline-first

```text
Продолжи проект «Ритм» в текущем workspace. Это этап 4 из 8. Этапы 1–3 должны быть рабочими.

Прочитай docs/project-brief.md, docs/work-status.md и реализацию workout/autosave. Запусти существующие тесты. Сначала составь карту изменяющих API-действий и их идемпотентных ключей.

Сделай тренировку реально offline-first:
- корректные manifest.json, PWA icons, standalone/display/theme и apple-touch metadata;
- Service Worker с версионируемым app shell cache, offline fallback и безопасной стратегией обновления;
- IndexedDB для снимка активного плана/сессии, локальных фактических данных и outbox;
- local-first сохранение каждого существенного действия до сетевого запроса;
- идемпотентная синхронизация outbox при online, повторном открытии и ручном retry;
- порядок зависимых действий и отсутствие дублей при повторной доставке;
- статусы «онлайн / офлайн / ожидает синхронизации / синхронизировано / ошибка»;
- восстановление введённых подходов после reload/закрытия страницы;
- корректное разрешение конфликтов optimistic locking без тихой потери данных;
- защита от двух вкладок через BroadcastChannel/Web Locks или безопасный fallback;
- сценарий обновления Service Worker без потери активной тренировки.

Не кешируй приватные HTML/API-ответы так, чтобы другой пользователь устройства мог их увидеть после logout; реализуй очистку пользовательских caches/IndexedDB при выходе или безопасное namespace. Добавь тестируемые pure-функции очереди и ручные сценарии: открыть онлайн → отключить сеть → добавить несколько подходов → reload → продолжить → вернуть сеть → убедиться в одной копии каждого действия. Проверь installability доступными средствами. Обнови документацию, CHANGELOG.md и docs/work-status.md.
```
